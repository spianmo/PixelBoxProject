# Obeing Pixel / 小川

PixelBox 的手机协同语音助手。368x448 屏幕上方为三维体素小猫，下方显示当前单轮的语音识别文本、后端公开执行状态和助手回复。支持浅色、暗色、待机、睡眠、唤醒、聆听、思考、播报、静音、异常、配对及等待手机同步状态。账号登录、权限和对话数据全部由手机管理；本示例没有设备账号登录或退出账号操作。

## 连接与账号同步

1. PixelBox 先通过设备系统设置连接 Wi-Fi，手机连接同一局域网。
2. 在 **Obeing Pixel Android APP** 打开 PixelBox 配对页并启动桥接。可以先配对设备，再在手机登录。
3. 启动本示例。它通过 `_obeing-pixel._tcp` 发现手机，在屏幕数字键盘输入手机显示的六位配对码，点击对勾。
4. 配对码正确即完成配对，无需在手机二次确认。手机未登录时，设备显示“请在手机登录”，保持连接等待手机同步账号；手机下发有效账号后才开启麦克风。
5. 说 **“你好小川”**，再说问题。NuttX + MultiNet7 在设备本地完成唤醒词识别，命中后向手机发送 `mic.start`；手机继续负责 STT、AI 对话和 TTS，设备同步字幕并从自己的扬声器播报。

企业 ID、账号、密码仅在手机填写，手机经 HTTPS 提交既有企业登录接口。PixelBox 不接收密码或企业 token，只显示手机下发的账号名称、企业标识、字幕和执行状态。设备右上连接图标进入连接页，可查看手机同步的身份，选择“断开手机连接”只关闭设备连接。

手机退出登录、登录过期或切换账号时，通过 `account.state` 推送新状态；设备立即停止旧音频并清空身份和单轮字幕，安全配对继续保持。手机重新登录后推送账号并恢复语音，不需要设备重新配对。设备未完成配对、已断线或授权已撤销时，账号推送不能开启麦克风。网络中断、手机关闭服务或撤销设备授权同样立即停止采音；正常断线、手机服务重启和设备应用重启后自动恢复已配对连接，无需再输入码；只有手机“忘记已配对设备”后才需要重新配对。设备手动断开会暂停自动重连，点按屏幕恢复。

账号快照携带递增的 `accountEpoch`。设备先停止旧音频并回传匹配的 `account.ready`，再开始新账号采音；手机在确认前拒绝输入。设备同时丢弃旧采音回调和旧账号快照，避免切账号时把排队的旧 PCM 归入新账号。

当前局域网桥接为 `ws://`，六位配对码在 120 秒内有效，正确输入后立即连接。两端持久保存独立的 256 位设备恢复密钥，自动重连只选择相同 phoneId 的手机。它不是传输加密：局域网内的音频、字幕和配对消息未使用 TLS。此实现适用于可信 Wi-Fi；设备 SDK 的 `wss://` 只接受可信 CA 证书，未采用关闭证书校验或自签名跳过验证。

## 操作

| 操作 | 行为 |
| --- | --- |
| 说“你好小川” | NuttX + MultiNet7 在设备本地识别唤醒词后开启一轮语音输入，并向手机发送 `mic.start` |
| 触摸小猫 / BOOT 单击 | 直接开启语音输入；思考、播报时打断当前轮 |
| 长按角色 700 毫秒 | 依次切换像素小猫 → 经典 Kitty → 女巫 Kitty → 小鱼 Kitty → 围巾 Kitty → 像素小猫 |
| 顶部麦克风 / BOOT 双击 | 停止或恢复采音 |
| 顶部半明半暗图标 | 浅色 / 暗色切换，保存到 `ob.theme` |
| 顶部连接图标 / BOOT 长按 | 手机连接页，查看同步身份或断开连接 |
| 倾斜设备 | QMI8658 的 X/Y 加速度驱动小猫三维旋转及水平 / 垂直位移 |
| 45 秒无对话 | 闭眼呼吸动画，仍等待唤醒词 |

普通及全屏主页都支持换装，每次长按只切换一款；在角色上短按会在松手时开始语音，
移动超过 12 个布局像素则取消本次手势，长按不会发送聆听或打断当前对话。
选择保存到 `ob.character`，重启恢复。连接页和配对键盘不触发换装，BOOT 长按仍打开连接页。
普通及全屏主页不显示角色名、换装说明或陪伴标语；待机和睡眠显示唤醒词，聆听、工具进度和对话字幕正常保留。

四款 Kitty 保留各自原图的构图：经典款为红蝴蝶结大头，女巫带弯帽、完整侧坐身体和扫帚，
小鱼款保留蓝色鱼形包边，围巾款保留粉色蝴蝶结、完整围巾和下身。
`src/kitty-patterns.ts` 保存原始图纸：女巫 46x47（1092 格）、小鱼 30x23（450 格）、
围巾 21x22（284 格），按用户网格图逐格提取。`src/kitty.ts` 只裁透明边，按可用区域的最大整格尺寸等比放大。
字幕区按实际内容预留高度，无对话时将空白区域让给 Kitty；完整保留身体与配件。
IMU 薄浮雕倾斜、呼吸及说话平移、眨眼和睡眠闭眼保留，不叠加小猫纵向挤压。
角色包围盒只覆盖实际画出的像素，避免全屏倾斜时背景恢复擦到波形和字幕。
不需要下载图片或增加固件图像资源。示例 07 共用同一套图纸及长按逻辑。

Kitty 渲染预先缓存睁眼和闭眼的列色段，每帧直接投影色段并合并相邻矩形，复用工作区，
避免逐点反算和大量临时对象造成 QuickJS 单次回调超过 1000ms 而触发 `InternalError: interrupted`。
`pnpm run test:kitty` 对四款形象、睁闭眼、三种区域与 40 个姿态共 960 场景检查像素和包围盒，
并约束绘图调用量。这项本地操作量统计不代表真机帧率或语音联调结果。
可运行 `node scripts/test-kitty-projection.mjs ../firmware/build/jsvm-host/qjs_bench` 补充桌面 QuickJS 耗时测试。

采音为 16 kHz 单声道 PCM16LE，每帧 128 ms / 4096 字节；固件用 IMA ADPCM 将上行压到 1030 字节，手机解码为 PCM 后送入识别，传输带宽约为原来的四分之一。这是有损语音编码。手机与固件必须同时更新；握手通过 `inputFormat` 确认编码支持。播报时本地暂停麦克风，收到 `audio.end` 后等待扬声器实际播完再发 `audio.played`，防止把扬声器尾音再次识别为唤醒词。手机桥接需保持运行。NuttX 固件使用本地 MultiNet7 模型检测“你好小川”，命中后才通知手机开始上行采音；桌面模拟器、旧固件或本地模型不可用时才回退手机唤醒。

下行 PCM 首播累积 256 ms 后开始播放，吸收网络批次和 JS 绘制调度抖动；小包不足阈值时，在收到首块后的 512 ms 定时任务中送入播放器，短回答在 `audio.end` 时立即送入。首播后持续写入同一环形流，不能因 `buffered()` 瞬时为零重复预缓冲，该数值不包含已送入 DMA 的采样。512 ms 是 JS 定时器的到期时间，实际执行仍受固件调度影响。取消、静音、断线或切账号都会清除尚未启动的任务；设备端提前播放以手机已经发来 PCM 为前提。

三维绘制和 WebSocket 收包共用 JS 线程。播报过程中音频余量低于 384 ms 时跳过该次绘制，先处理收包，余量充足后继续动画；`audio.end` 后恢复正常绘制。设备内建 `px.voice` 或其它共享麦克风订阅运行时也使用同一调度预算，不依赖示例自己的 `micActive` 标志。每次慢帧完成后按实际耗时给实时音频留出至少 64 ms、通常两倍绘制耗时的空闲窗口；音频上行有待发送数据时优先排空网络队列。这样避免真机超过 300 ms 的重绘反复阻塞音频。音频紧张时画面会暂缓更新，输入事件仍正常处理。

## 三维小猫

默认像素小猫的轮廓、眼位、表情及待机形变恢复到2026-09-09中午前的版本 `0935617`；不再追加半身或常驻微笑。

`src/model.ts` 按提供的 `像素小猫` 多视角 JPEG / WebP 素材重建 13x21x21 三维数组。双尖耳、方脸、白色主体、红黄左边与青蓝右边来自参考形象。只投影外壳粒子并合并为扫描行，同色主体无需深度排序；眼睛、嘴位于模型前表面，随同一矩阵投影。IMU 请求 50 Hz 最新样本，姿态和位移直接跟随，不再叠加低通等待；最大倾角和主体区边界限制仍保留。目标帧率设为 30 FPS，该值不是实际帧率保证。

06 / 07 的 IMU 转向最大附加角为左右 ±1.2rad、上下 ±0.6rad，位移为水平 ±18px、垂直 ±12px。像素故障强度使用未钳制的 X/Y 合成加速度（含重力投影），正负方向等效：0.06g 内不额外增强，1.5g 达到最强；彩边分离、眼部重影、扫描条数量/长度及跳动速度随强度增加。所有彩边和扫描条都受主体区域裁剪，局部刷新会清理上一帧的效果。

06 / 07 共用的渲染器在动画帧只恢复上帧小猫包围盒和相交网格；字幕变化只清理字幕区域，页面 / 主题变化才整屏刷新。中文排版缓存单字宽度，稳定字幕不重复排版或绘制。彩边跳过最终被白色主体覆盖的区域：本机 99 个姿态的逐像素等价测试中，小猫填充面积从 8,535,765 降至 2,540,035 像素，减少 70.2%；这项桌面操作量统计不代表真机 FPS 或 IMU 延迟。连续帧、字幕更新和页面切换也与整屏重画逐像素比较。

`thinking.status` 只显示手机转发的公开工具执行状态 / 摘要；本示例不构造或显示模型隐藏推理。底部无长历史列表，新一轮开始清空上轮字幕。

## 音频与动画同时运行的实机回归

设备空闲且未配对时，在仓库根目录执行 `node tools/check-obeing-audio.mjs <设备IP> <本机局域网IP> 20`。
追加 `--fullscreen` 可验证全屏三维动画及字幕同时运行。
它使用 example06 的真实 `onMessage` 入口、播报动画与原生扬声器，发送 20 秒本地测试音，验证字节总量、
空缓冲次数与动画仍在更新。这个检查会发出测试音，但不使用企业账号或云端服务；结束后恢复原页面。
配对键盘页没有三维绘制负载，不能用仅在该页通过的 PCM 探针证明播报连续性。

## 真实手机协议探针

Android 仓库 `PixelBoxBridgeInstrumentedTest` 绑定真实服务，验证原生 / 模拟器握手、未授权 PCM、网页来源与错误路径的拒绝。不会修改企业登录状态或调用云端。可加 `-e obeingProbeMs 25000` 保持服务 25 秒，从 logcat 的 `ObeingBridgeProbe: PORT=...` 取得端口。

```bash
adb forward tcp:18888 tcp:<手机服务端口>
node scripts/probe-obeing-android.mjs ws://127.0.0.1:18888/pixelbox
adb forward --remove tcp:18888
```

这个探针运行真实设备入口与模拟器的真实 WebSocket 包装代码，只替代硬件接口与已知设备发现地址，实际连接手机生产 WebSocketServer。分别验证无 Origin 的原生设备与 `Origin: null` 的模拟器提交无效配对码后都收到 `error.code=pair_invalid`，以 1008 关闭连接，收不到账号快照，采音启动数为零。它不验证已授权企业对话、云端 ASR/TTS 或物理 PixelBox 音频。

上行使用有界队列（最多 64000 字节 PCM），原生发送队列暂满时按 16ms 调度重试，每次最多提交 4 条；切账号/取消先清旧 PCM。音频积压超过 2 秒时暂停采音并重建本轮识别，保留设备连接和配对；控制消息连续 15 秒无法提交或底层传输失败才按 1/2/4/8/15 秒退避重连。采音时积压未排空不绘制；采音和播报期间，完成绘制后至少留出本次绘制耗时两倍、且不小于 64ms 的空闲时间。

设备底层和手机两端均设置 TCP_NODELAY，上行帧头和音频分次写入不再等待 Nagle 合包。这个改动必须更新 ESP 固件，单独 push example06 不生效。真实手机连接可用 `node tools/observe-obeing-uplink.mjs <设备地址> 180` 观测，断线与 socket 替换均判失败，不记录音频或识别内容。

原生发送先在 worker 等待 TCP 可写，等待上限和单次网络操作超时均为 10 秒；写帧前的等待不占发送锁，也不重发已部分写入的帧。`node tools/check-websocket-backpressure.mjs <设备地址> <本机IPv4>` 将服务端 TCP 接收窗口限制到 4096 字节并暂停读取 4 秒，检查同一连接完整、有序发完 64 KiB 测试数据。受控背压通过不代表当前 Wi-Fi 的持续语音已经通过，真实连接探针还会记录 `audioRecoveries`。
